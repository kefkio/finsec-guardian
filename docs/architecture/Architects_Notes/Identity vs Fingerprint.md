Architect's Note #22 – Identity vs. Fingerprint

One of the most subtle concepts in a security scanner is distinguishing between an entity's identity and a finding's fingerprint.

They solve different problems:

Entity ID (UUID): Identifies this specific Finding instance in our system. It is generated by the domain and remains stable for the lifetime of that entity.
Fingerprint: Identifies the underlying vulnerability. If two separate scans detect the same issue in the same location with the same characteristics, they should produce the same fingerprint, even though they are different Finding entities with different UUIDs.

This distinction enables features such as deduplication, regression tracking, historical comparisons, suppression, and trend analysis. In FinSec Guardian, the UUID answers "Which entity is this?", while the fingerprint answers "Which vulnerability is this?
